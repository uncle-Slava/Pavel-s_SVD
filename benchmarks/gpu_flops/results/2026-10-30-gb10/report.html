How this was measured

  • Hardware and software: NVIDIA GB10 (CUDA capability 12.1), PyTorch 2.14.1+cu130, CUDA 13.0, repository Pavel-s_SVD at main on 30 October 2026. The GPU was shared with another, idle process.
  • Matrices: one square Gaussian matrix per size, drawn in float64 with seed 1000 + n and cast to float32 (or kept in float64). Every method gets rank = n, so truncated methods also return a full SVD.
  • Timing: 3 warm-up runs, then 20 timed runs measured with CUDA events after synchronizing; median and minimum reported. A method whose first run took over 2 s got 1 warm-up and 3 timed runs. Methods slower than 5 s at n = 128 were not run at n = 256.
  • FLOPs: matmul FLOPs measured with torch.utils.flop_counter. The repository's Householder, Cholesky, triangular-solve, Jacobi and bdsqr primitives use element-wise kernels, not matmul. Their FLOPs are counted exactly from each call's shape and its actual sweep or iteration count, including masked work. Not counted: float64 secular-equation solves in the divide-and-conquer methods, norms and sorting. torch.linalg.svd uses 21n³.
  • Accuracy is computed in float64 from the returned factors.
  • Raw files: benchmarks/gpu_flops/results/2026-10-30-gb10 (results.json, flops.json, algorithms.json, scorecard output); scripts in benchmarks/gpu_flops.
